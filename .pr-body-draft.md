### Problem
- Under `bun test --retry`, the second attempt of a `node:test` test fails with `cannot set plan more than once`. It also keeps the first attempt's failed subtests and `t.after` hooks.
- `createTopLevelTestRunner` (`src/js/node/test.ts:2561`) runs every attempt on one `TestNode`. It reports with `done(error)`, which bun:test charges to the running test when its own timeout already ended this one.

### Fix
- Each later attempt gets a new `TestNode`, built from a copy of the options taken at the declaration.
- A replaced attempt whose body is still pending gets its mocks reset and its `t.after` hooks run first.
- The runner returns a promise and rejects it on failure. bun:test ignores the rejection of a test it timed out (`bun_test.rs:956`).
- Verified: 2 new tests in `test/js/node/test_runner/node-test.test.ts` fail on main. Also the vendored node tests that use `node:test`.

### Background
- `TestNode` is the shim's record of one test: plan, hooks, subtests, mocks. bun:test calls the registered callback again for each retry.
- bun:test ends a test by its own timer (5 s, `--timeout`) and does not tell the shim, whose run reports later.
- Considered a shim check that drops a replaced attempt's verdict. It misses a test with no newer attempt.

### Downsides
- A plain test costs +820 instructions with the JIT off (+1.2%). A test declared with options makes one more object (112 B).
- A late failure of a test that an uncaught error ended is now "Unhandled error between tests", as in bun:test.
- Options are read once at the declaration, as in Node.

#### Left out

- `t.signal` still never aborts, and the `signal` option of a test still does nothing. #39287 does that on top of this PR.
- bun:test's own timeout still ends a test without telling the shim, so the hooks of that test run while the next test runs. #43803 and #47461 work on that.

#### Related

- #43751 and #43803 also make a new `TestNode` per attempt, inside larger changes. This PR is that part alone, so that they can drop it.
- #47461 gives bun:test's timer 5 s more than a test's own `timeout`. It removes one way to reach the late report. This PR makes the late report harmless for every way.
